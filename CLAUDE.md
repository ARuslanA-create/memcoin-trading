# VK Games — общие правила разработки

Монорепо с играми для платформы VK Mini Apps. У каждой игры своя папка и свой `CLAUDE.md`
с концепцией. Правила из этого файла обязательны для **всех** игр без исключений.

## Структура

```
vk games/
├── CLAUDE.md                      ← этот файл: обязательные правила для всех игр
├── _shared/
│   ├── vk-rules.md                ← выжимка официальных правил размещения VK
│   ├── checklist.md               ← чек-лист перед отправкой на модерацию
│   └── moderation-lessons.md      ← реальные отказы модерации и как их не повторять
└── <игра>/
    ├── CLAUDE.md                  ← концепция и специфика конкретной игры
    └── ...
```

Перед любой работой над игрой читай `_shared/moderation-lessons.md` — там накопленные
реальные замечания модераторов. Это самый частый источник отказов.

## Жёсткие требования (нарушение = отказ модерации)

### Монетизация
- Внутриигровая валюта покупается **только за Голоса VK**. Никаких рублей, VK Pay,
  карт, «₽» в интерфейсе магазина. Единственный корректный путь — `VKWebAppShowOrderBox`
  с `type: 'item'`.
- Платежи должны реально работать. «Демо-режим», заглушки и `alert('скоро')` — отказ.
- Валидация покупки на сервере через Callback API / Bots Long Poll. Нельзя начислять
  товар только по клиентскому ответу.
- Валюту нельзя выводить, обменивать на деньги/товары, передавать другим игрокам
  (кроме единоразового дарения).
- Реклама: только штатная VK (`VKWebAppShowNativeAds`). Сторонние сети запрещены.
  Не показывать на старте и в онбординге, не чаще 1 раза в 30 секунд, минимум 20px
  от функциональных элементов.

### UI и вёрстка
- **Safe area обязательна.** Использовать `env(safe-area-inset-*)` для верха и низа.
  Нижняя часть интерфейса не должна срезаться — это замечание уже получали.
- **Не занимать верхнюю правую зону.** Там VK рисует свои кнопки (`···`, `X`,
  «ВКонтакте»). Все свои элементы верхнего бара смещать ниже и левее, либо
  запрашивать реальные insets через `VKWebAppGetConfig` / событие `VKWebAppUpdateConfig`.
- Проверять на 320px, 375px, 414px и планшете. Ничего не должно перекрываться.
- Поддержка светлой и тёмной темы (`VKWebAppUpdateConfig` → `scheme`).
- Все тексты на русском, без опечаток. Кнопки закрытия и отказа не маскировать.
- Спиннер/прогресс при загрузке, заглушка при ошибке.

### Обязательная функциональность
- `VKWebAppInit` при старте — без него приложение не запускается.
- **Онбординг обязателен.** Не один экран с текстом, а пошаговое обучение основной
  механике с возможностью пропустить. Модерация отдельно придирается к его качеству.
- Соцшер (`VKWebAppShare` / `VKWebAppShowWallPostBox`) должен реально открывать
  диалог и обрабатывать успех/отказ. Нерабочая кнопка шера — отказ.
- Минимум 10 минут игрового времени, полный баланс/жизни при первом запуске.
- Жизни и энергия восстанавливаются автоматически по таймеру.
- Полноценное стартовое меню, а не сразу геймплей.
- Прогресс синхронизируется между платформами (сервер или `VKWebAppStorageSet`).
- Пользовательское соглашение и политика конфиденциальности доступны из приложения.

### Социальные механики
- Нельзя ограничивать функциональность за отказ от соцдействий и уведомлений.
- Нельзя предлагать подписку/промо/рекомендацию при первом запуске.
- Отказ пользователя запоминать, повторять предложение не чаще раза в месяц.

## Технические договорённости

- Игры пишутся как одностраничные HTML-файлы со встроенными стилями и скриптами
  (так они сейчас устроены — не разбивать на бандлер без явной просьбы).
- VK Bridge подключается через CDN `unpkg.com/@vkontakte/vk-bridge/dist/browser.min.js`.
- Каждый вызов VK Bridge оборачивать в `try/catch` с фолбэком: игра должна
  оставаться играбельной вне VK (для локальной отладки), но без рублёвых заглушек.
- Никакого тестового контента, `console.log` отладки и текстов-рыбы в релизной сборке.

## Перед отправкой на модерацию

Пройти `_shared/checklist.md` целиком. Если модерация вернула замечания —
дописать их в `_shared/moderation-lessons.md`, чтобы следующие игры их не повторяли.
